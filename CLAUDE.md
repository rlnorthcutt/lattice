# CLAUDE.md

## Project Overview

Lattice is a lightweight, layout-first CSS utility toolkit providing a 12-column grid system, spacing utilities, and component helpers via two composable source files (`lattice.css` and `lattice.extra.css`).

## Architecture

- **Two source files, three distribution bundles:**
  - `lattice.css` — core grid and layout utilities (standalone, no dependencies)
  - `lattice.extra.css` — spacing, flex, display, overflow, and accessibility helpers (extends core)
  - `lattice.full.css` — combined bundle (core + extra), generated by the CI workflow
- **CSS custom properties** are the configuration surface. The spacing scale derives from `--lat-space` as a base token. Breakpoints are `sm/md/lg/xl/xxl`.
- **No JavaScript, no build tooling required for users.** The library is pure CSS.
- **Docs site** lives in `docs/` and is served via GitHub Pages. Static assets (`docs.min.css`, `docs.min.js`) are pre-built and committed.

## Development Conventions

- **Source files only:** `lattice.css` and `lattice.extra.css` are the only files to edit. Never hand-edit anything under `docs/static/` or `dist/` — those are generated.
- **CSS custom properties for all configurable values.** Avoid hardcoded values; use tokens derived from `--lat-space` for spacing and named breakpoint variables.
- **Responsive utilities** follow the `{property}-{breakpoint}` pattern for breakpoints `sm`, `md`, `lg`, `xl`, `xxl`.
- **Utility scale:** spacing uses a 0–5 integer scale built on fraction tokens of `--lat-space`.
- **No preprocessors.** The source is plain CSS; avoid introducing Sass, PostCSS, or other preprocessors.

## Common Tasks

### Local development
Serve the docs site locally with any static file server:
```sh
npx serve docs/
# or
python3 -m http.server --directory docs/
```
Then open `http://localhost:5000` (or the port shown).

### Minification / build
The CI workflow handles minification automatically on push to `main` when source CSS changes. To run manually:
```sh
npm install -g clean-css-cli
cleancss -o dist/lattice.min.css lattice.css
cleancss -o dist/lattice.extra.min.css lattice.extra.css
cleancss -o dist/lattice.full.min.css lattice.css lattice.extra.css
```

### Updating docs styles
Edit the source doc stylesheets in `docs/css/`, then regenerate `docs/static/docs.min.css` and commit both. Do not edit `docs/static/docs.min.css` directly.

## Known Issues / What to Avoid

- **Do not copy `lattice.full.css` (unminified) where `lattice.full.min.css` is expected.** The CI workflow has a bug where the non-minified full bundle is copied to `docs/css/` — be aware that the docs site currently serves unminified CSS.
- **Do not use floating CDN references without a version pin.** CDN links should include a release tag (e.g. `@v1.0.0`) so consumers are not silently broken by future changes.
- **Do not add SRI-less CDN `<link>` tags** in documentation examples. Always include a version pin and recommend adding an `integrity` attribute.
- **Do not duplicate embedded `<style>` blocks across doc pages.** Shared doc styles belong in `docs/css/zzOverrides.css` or a dedicated shared stylesheet, not copy-pasted into each HTML file's `<head>`.
- **Do not commit generated `dist/` artifacts manually.** Let the CI workflow produce them to avoid conflicts and history pollution.
- **Do not introduce JavaScript dependencies** to the core library. The library must remain pure CSS.
- **Avoid adding features to `lattice.extra.css`** that overlap with or duplicate utilities already in `lattice.css`. Keep core/extra responsibilities clearly separated.
