Why Lattice

Most layout tools miss in one of two directions. Some do too little, so you hand-roll a grid system on every new project. Others ship thousands of utility classes you will never type, along with the bundle size that comes with them. Lattice aims at the 90% case: equal columns, responsive breakpoints, and the occasional unequal span. That covers nearly every layout you actually build.

2.3 KB for the grid

Core is roughly 2.3 KB minified. Take everything, utilities included, and you are at about 13 KB.

Nothing to install

One <link> from a CDN. No build step, no PostCSS plugin, no class scanner watching your files.

It leaves your CSS alone

Lattice styles layout. Your headings, buttons, forms, and colors keep whatever you already gave them.

Tokens are plain CSS

Container width, spacing rhythm, and gaps are custom properties. Override them in your own stylesheet and reload.

You'll still write custom CSS. Every real project does, and Lattice doesn't try to stop that. The goal is a small, predictable layout layer that keeps your total CSS smaller than pulling in a large framework and then overriding half of it.

If you want components and typography too, load Ivy alongside it. That pairing is what this documentation site runs on.

Two layers

Lattice ships as two files so you only send what you use. Core handles the simple case: equal columns with responsive breakpoints. Extra adds span-based layouts and utilities for the times equal columns fall short. Start with Core and add Extra when a design calls for it.

Core — lattice.css

Equal-column grids with responsive breakpoints, the pattern behind most pages. Pick a column count per breakpoint and skip the math.

  • Master page grid (.lattice)
  • Full-bleed and centered sections
  • 12-track component grid (.grid)
  • Equal-column helpers (.grid.col-N)
  • Responsive breakpoints (sm → xxl)
  • Minimal display and visibility utilities
View core demo →

Extra — lattice.extra.css

Span-based columns for asymmetric layouts, plus the spacing, flex, and positioning helpers you reach for while building them.

  • Spacing scale (padding, margin, gap)
  • Responsive display toggles
  • Unequal column spans (.span-N)
  • Flex direction, alignment, order
  • Positioning, overflow, z-index
  • Screen-reader utilities

Installation

Pick the option that matches how much you need. Every one of them is a link tag you can paste right now.

Core only

The page grid and equal-column helpers, nothing else. Good when you already have a spacing system you like.

<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/rlnorthcutt/lattice/dist/lattice.min.css">

Core plus Extra

Adds spacing, spans, flex helpers, and positioning utilities as a second file.

<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/rlnorthcutt/lattice/dist/lattice.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/rlnorthcutt/lattice/dist/lattice.extra.min.css">

Full bundle

Core and Extra in one request. Simplest choice for most projects.

<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/rlnorthcutt/lattice/dist/lattice.full.min.css">

With Ivy (recommended)

Load Ivy first for classless HTML defaults, then Lattice for layout control.

Quick start

Add .lattice to your page shell and the grid takes over. Direct children sit at centered container width by default. Add .full-width to any section that should run edge to edge.

<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">

<body class="lattice">
  <header class="full-width">…</header>  <!-- bleeds to viewport edges -->

  <main class="container">
    <!-- Equal columns: stack → 3 cols at md+ -->
    <div class="grid col-1 md-col-3 gap-3">
      <article>A</article>
      <article>B</article>
      <article>C</article>
    </div>

    <!-- Unequal columns (requires Extra) -->
    <div class="grid gap-3">
      <aside class="span md-span-4">Sidebar</aside>
      <section class="span md-span-8">Content</section>
    </div>
  </main>

  <footer class="full-width">…</footer>
</body>

That is the whole mental model. A shell, a grid, and a column count per breakpoint.

Customization

Custom properties drive everything. Redefine any token in your own stylesheet and Lattice picks it up, no rebuild involved.

:root {
  --lat-container-width: 1200px;  /* max content width (default: 1024px) */
  --lat-space: 1.125rem;          /* spacing rhythm base (default: 1rem) */
  --lat-gap-x: 1.5rem;            /* horizontal grid gap */
  --lat-gap-y: 1.5rem;            /* vertical grid gap */
}
Safe-area insets

The master grid gutters use env(safe-area-inset-left/right) so content clears the notch on modern phones. Include viewport-fit=cover in your viewport meta to switch it on.

Browser support

Lattice builds on modern CSS. Each feature below is baseline-supported in current Chrome, Firefox, Safari, and Edge.

FeatureUsed for
CSS Grid (grid-template-columns)The master page grid and the .grid component grid, with no flexbox tricks and no JavaScript
env(safe-area-inset-*)Fluid outer gutters that respect notched devices
Logical propertiespadding-inline, margin-inline, and friends for the spacing scale
color-mix()The translucent, blurred background on .sticky
backdrop-filterBlur behind .sticky elements, including this page header
aspect-ratio.aspect-square and .aspect-video
position: stickySticky headers and on-page navigation
